# Listing Health Scheduled Task import

## Purpose

The Listing Health page accepts research findings generated by a ChatGPT Scheduled Task. The import is a review queue, not a direct database sync. Imported findings are stored in the current browser's local storage until applied or dismissed.

## Scheduled Task workflow

1. A recurring ChatGPT task reviews public Bubba Hub directory pages and publicly available organiser/venue websites.
2. It reports only evidence-backed missing or changed details, possible anomalies, and optional description improvements.
3. Copy the JSON block from the task report.
4. In Admin → Listing Health Check, choose **Import Scheduled Task JSON**, paste the block, and validate it.
5. Open **Review imported findings**. Apply each item individually or dismiss it.
6. The dashboard update endpoint validates the admin session, CSRF token, listing ID, field allowlist and value before saving.

ChatGPT Scheduled Tasks do not have direct access to Bubba Hub's private admin database. This manual handoff is deliberate: no task can publish changes without an admin review.

## JSON contract

```json
{
  "schema_version": 1,
  "generated_at": "2026-11-16T09:00:00+00:00",
  "findings": [
    {
      "activity_id": 123,
      "title": "Example activity",
      "field": "description",
      "finding": "The public listing has no description.",
      "suggested_value": "A proposed factual description...",
      "source_url": "https://example.org/",
      "confidence": "medium"
    }
  ]
}
```

Each finding must include a positive integer `activity_id` and a string `suggested_value` (or `suggested_description`). Supported direct-edit fields are `description`, `short_description`, `category`, `age_range`, `website`, `booking_url`, `contact_email`, `contact_phone`, `facebook_url`, `instagram_url`, `town`, `region`, `postcode`, and `venue_name` / `address` where the venue schema supports them. Fields not supported by the current schema must be opened in the full listing editor rather than forced into a different column.

## Safety boundaries

- Never invent a listing ID, source, phone number, email, address, price, session time or age range.
- Distinguish verified facts from suggestions and low-confidence matches.
- Do not infer that a listing is closed because a website is temporarily unavailable.
- Description suggestions must be factual, neutral and based on sourced information.
- Do not include personal data that is not already publicly displayed for the listing.
- The import queue is local to the browser and is not a cross-device or server-side queue.
- Listing merge is not automated. Potential duplicates need a separate relationship-aware merge workflow because activities may have linked venues, sessions, organiser accounts, bookings and saved/planned references.
